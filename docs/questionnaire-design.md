# 深度调研与多脚本设计

> 状态：规则约束与 DeepSeek AI 脚本生成已接通。

## 产品流程

```text
五步调研 → 形成门店 IP 档案 → 五类策略评分 → AI 生成三套差异化脚本
→ 程序校验事实、权限、CTA 和结构 → 老板比较并选择 → 按详细分镜拍摄
```

## 五步调研

1. **门店档案**：店名、城市、商圈、菜系、经营年限、人均、招牌菜和经营方式。
2. **老板本人**：称呼、家乡、真实性格、入行原因、经营困难、经营成就、出镜方式、语言和内容边界；个人经历只有主动授权后才会发送给 AI。
3. **真实证据**：同行差异、食材证明、制作过程、顾客表扬和顾客误解。
4. **顾客目标**：核心顾客、消费场景、需求、顾虑、经营问题和内容目标。
5. **拍摄条件**：平台、风格、时长、可拍区域、后厨/顾客权限、设备、每天时间和更新频率。

数据以 `ResearchProfile{store, owner, audience, shooting}` 保存。核心问题只有店名和招牌菜强制填写，其余问题可逐步补充；信息不足会降低对应策略分数，而不是阻止生成。

## 内容策略

| 策略 | 主要依据 | 典型目的 |
|---|---|---|
| 招牌菜爆点型 | 菜品、差异、食材证明、到店目标 | 食欲和转化 |
| 老板故事型 | 人设、入行原因、困难、成就、出镜条件 | 人物记忆和信任 |
| 后厨揭秘型 | 后厨权限、可视化工艺、食材证据 | 品质证明 |
| 顾客问题型 | 顾虑、误解、可验证事实 | 回应质疑和建立信任 |
| 经营纪实型 | 可拍场景、经营年限、拍摄时间 | 连续栏目和长期更新 |

规则引擎给所有策略计算 0–100 的发布前适配分，并选择排名最高的三个。老板不出镜时老板故事会被排除；后厨不可拍时后厨揭秘会被排除。DeepSeek 根据这三种选题生成连贯成稿，每个候选包含推荐原因、拍摄难度、所需场景和六个连续镜头。程序随后检查策略数量、CTA 重复、禁用表达、个人经历授权和不可拍区域；不通过时自动携带错误原因重试一次。

每条分镜除台词、地点、景别和时长外，还保存镜头目的、主体、动作步骤、手机倍率与距离、运镜、声音、光线、道具、字幕、剪辑提示、常见错误和重拍标准。旧脚本缺少这些字段时使用空值兼容。

## 适配分的边界

适配分只用于发布前选择，不代表平台表现。前端明确提示：真正的长期权重应由 2/6 秒留存、平均观看、完播、关注、主页访问、团购点击和到店核销等数据更新。

当前版本没有自动接入发布数据，因此不会根据一次生成结果永久改变策略权重。

## 兼容方案

- 原 `BossInfo` 和 `/script/template` 保留，旧项目可以继续打开。
- 旧项目首次读取 `research` 时，会根据已有 `BossInfo` 生成深度档案草稿。
- 生成新方案不会覆盖当前脚本；只有用户主动选择候选后才更新 `script.json`。
- 被选中的脚本仍使用 1-based 镜头编号，后续素材上传和剪辑流程无需改造。
